# ClaimGuard-KR

**사람 검토와 AI 위험평가를 갖춘 보험금 청구서류 접수 자동화**

📄 한 장 요약 페이지: https://claude.ai/artifact/7QR5eQEP7ShAT5PUbrWg6M

DB손해보험 양식 보험 서류(AI Hub 공개 데이터, 값은 가상)를 대상으로
**서류 분류 → 항목 추출 → 접수 검증 → 처리 결정**을 자동화하고,
2026년 6월 개정 **「금융분야 인공지능 가이드라인」의 위험평가 체계**로 시스템 자체를 평가한 개인 프로젝트입니다.

> DB손해보험 양식의 AI Hub 공개 데이터를 사용한 개인 프로젝트이며, DB손해보험과 관련이 없습니다.

## 왜 이 문제인가

- 실손 청구 전산화(실손24) 의료기관 연계율은 28.4%(2026.4), 전체 청구 중 실손24 이용은 4.6%에 그쳐 청구 서류 대부분이 아직 종이·사진으로 접수된다.
- 접수 단계의 서류 분류·항목 입력·오기재 확인·보완 요청은 수작업 비중이 크다.
- 개정 가이드라인은 보험금처럼 계약자에게 영향이 큰 AI에 **사람의 실질적 검토, 설명, 사후 점검**을 요구하고, 위험을 점수(25/50/75점)로 등급화하는 방식을 제시했다. 보험사 중 AI 거버넌스 의사결정기구를 둔 곳은 7.5%(금감원, 2025.4)다 ([라이센스뉴스](https://www.lcnews.co.kr/news/articleView.html?idxno=208587)).

## 구조

```
서류 이미지
  → 서류 분류      8종 양식을 썸네일 모양으로 판별
  → 항목 추출      엔진 A: PaddleOCR Zone OCR (로컬, 무료)
                   엔진 B: Claude (구독 CLI, 외부 모델) — 실패 시 엔진 A로 자동 대체
  → 접수 검증      규칙 R01~R11 + 기준 데이터(KCD-9, KSCO 8차, 금융회사코드, 도로명주소 API)
  → 처리 결정      자동접수 / 보완요청(고객 안내문 자동 작성) / 담당자검토
  → 감사 로그      AI 결정·담당자 수정·최종 확정을 SQLite에 기록
AI 위험평가        가이드라인 예시표(16개 항목, 100점)로 두 엔진 시나리오 평가
```

| R06 | 연락처·이메일 형식 | 보완요청 |
| R07 | 주소 실재 (도로명주소 API, 장애 시 확인불가) | 보완요청 / 담당자검토 |
| R08 | 진단명 → KCD-9 질병코드 | 담당자검토 |
| R09 | 직업 → KSCO 8차 직업코드 | 담당자검토 |

| R11 | 예금주 ≠ 피보험자 → 위임장·인감증명서 | 추가서류 |

## 결과

데이터: AI Hub「OCR 데이터(금융 및 물류)」보험 부분 — DB손해보험 양식 8종, 학습 12,788장 / 검증 1,598장. 손글씨 칸 값과 좌표 라벨을 양식 칸 위치에 배정해 **항목별 정답을 자동 생성**(배정 실패 0.01% 이하).

**서류 분류**: 검증 1,598장 **100%** (OCR 없이 썸네일 거리 비교)

**항목 추출** — 같은 청구서 100장(구양식 50 + 신양식 50)

| | 엔진 A (PaddleOCR, 로컬) | 엔진 B (Claude, 외부) |
|---|---|---|
| 칸 완전 일치율 (구 / 신) | 64.3% / 68.0% | **87.8% / 85.3%** |
| 글자 오류율 (구 / 신) | 15.1% / 13.5% | **4.8% / 5.9%** |
| 장당 처리 시간 | **0.5~0.7초** | 13.5~23.0초 |
| 확신 높은 칸 / 낮은 칸 정확도 | 81~84% / 33~37% | 95~96% / 55~60% |
| 이미지 외부 전송 | 없음 | 있음 |

엔진 A 전체(청구서 400장): 칸 완전 일치율 64.8% / 70.3%, 확신도 0.85 이상 칸 79.6% / 83.2%.

**처리 결정** (엔진 A, 400장)

- 잘못된 자동접수(정답은 문제가 있는데 자동접수): **0건**
- 확신도 기준 0.85를 적용하면 사실상 전 건 담당자검토 → 현재 정확도에서는 "자동화"보다 "담당자 보조"가 맞다.
- 규칙별 결정 일치율(정답 값 vs OCR 값): 필수 칸 R01이 62~69%로 가장 약함(빈칸 오인식), 진단명 코드 R08 71%, 나머지 90% 이상. 엔진 B는 R01 88%.

**AI 위험평가** (가이드라인 예시표, 수행률은 작성자 판단 + 측정 근거)

| 시나리오 | 총 잔여 위험 | 등급 | 가장 큰 차이 |
|---|---|---|---|
| 엔진 A + 담당자 검토 | 27.4점 | 중위험 | — |
| 엔진 B + 담당자 검토 | 43.8점 | 중위험 (고위험 근접) | 보안성 5.4 → 18.6 (외부 전송, 위탁, 사용량 한도 장애) |

## 발견한 것

1. **정확한 엔진이 더 안전한 엔진은 아니다.** 엔진 B는 20%p 더 정확하지만 개인정보 외부 전송·외부 의존 때문에 위험 점수는 더 높다.
2. **언어모델 편향**: 엔진 B는 드문 성씨를 흔한 성씨로 바꿔 읽었다(곡→곽, 뢰→최, 묘→표). 이름 오류는 본인 확인·지급 오류로 이어질 수 있다.
3. **외부 의존 장애를 실제로 겪었다**: 일괄 추출 중 구독 사용량 한도로 100장 중 15장이 실패했다. 엔진 A 자동 대체 경로를 둔 근거.
4. **평가 지표를 정직하게**: 데이터 값이 무작위라 거의 모든 서류가 여러 규칙을 위반한다. 전체 결정 일치율(92~99%)은 부풀려진 수치라 규칙별 일치율을 함께 본다. 금액 칸의 "원"·쉼표 표기 차이는 두 엔진 모두 숫자만 비교하도록 보정했다.

## 한계

- 데이터 값이 가상이라 자동접수 비율, 실제 사기·지급 판단은 측정할 수 없다. 진료비 영수증은 공개 데이터가 없어 다루지 않았다.
- 체크박스(상해/질병/교통사고 등)는 라벨이 없어 제외했다. 청구서 외 6종은 분류만 한다.
- KCD-9·KSCO는 공식 명칭만 있어 "유방암"처럼 흔히 쓰는 이름은 매칭되지 않는다(담당자검토로 넘김).
- 위험평가 수행률은 작성자 한 사람의 판단이다. 독립 검증, 고객 이의제기 절차, AI 활용 고지는 구현하지 않았다.

## 실행

```bash
py -3.10 -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
# data/reference/ 에 AI Hub 데이터, KCD-9 DB masterfile, KSCO 8차 분류항목표 PDF, 금융회사코드, 가이드라인 PDF를 둔다
# .env 에 API1=<도로명주소 승인키>

.venv/Scripts/python -m scripts.build_ground_truth      # 항목별 정답
.venv/Scripts/python -m scripts.build_classifier        # 서류 분류기
.venv/Scripts/python -m scripts.run_eval extract        # 엔진 A 평가
.venv/Scripts/python -m scripts.run_claude_batch        # 엔진 B 100장 (claude CLI 필요)
.venv/Scripts/python -m scripts.run_eval compare        # 엔진 비교
.venv/Scripts/python -m scripts.run_decision_eval compare
.venv/Scripts/python -m pytest                          # 테스트 85개
.venv/Scripts/streamlit run app.py                      # 화면
```

설치를 마친 뒤에는 **`start_app.cmd`를 더블클릭하면 앱이 켜지고 브라우저가 열립니다.** 끌 때는 `stop_app.cmd`를 더블클릭합니다 (포트 8501).

| 화면 | 내용 |
|---|---|
| 서류 접수 | 서류 선택·업로드 → 엔진 선택 → 결정·사유·고객 안내문·칸별 확신도 |
| 검토 대기함 | 확신 낮은 칸부터 값 수정 → 재검증 → 최종 처리 확정 |
| 성능 비교 | 평가 결과 표·그래프 |
| AI 위험평가 | 두 시나리오 비교, 항목별 슬라이더로 직접 평가, 보고서 내려받기 |
| 감사 로그 | AI·담당자 결정 이력, 값 수정 이력 |
